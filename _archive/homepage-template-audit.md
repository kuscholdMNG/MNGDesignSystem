## 2. Production pattern (shared across OC Register, Denver Post, Mercury News)

All three sites share one scaffold:
1. Masthead: weather + date (left) · logo (center) · Subscribe/Log in + search (right)
2. Primary section nav
3. "Trending:" strip
4. Lead package: headline + hero image/gallery + related list, a "Latest Headlines" rail, and a rail ad
5. "Most Popular" numbered list (1–10, two columns of 5) with a sponsored-content or ad module beside it
6. Repeating category rail modules (lead item w/ image + secondary headline list), 1 or 3 across
7. Horizontal card carousel (varies by site — see 3.6)
8. Photo gallery module
9. Ad slots woven between modules (standard IAB sizes: 970x250, 728x90, 300x250, 300x600, 320x50)
10. Multi-column footer with logo lockup + legal links bar

What varies per site: nav labels, footer column composition (OCR: Subscribe/Marketplace/About/Advertising/Contact/Partners — Mercury News: News Alerts/Contact/Advertise/Subscribe), lead-package media (OCR = static image, Denver Post = image gallery), and a few site-specific modules (Mercury News has an "Upcoming Events" calendar carousel OCR doesn't).

This confirms one generic template with a couple of swappable modules should cover the footprint.

### 3.2 Section titles ("SECTION TITLE ▸", "SPORTS ▸", etc.) — ✅ RESOLVED 2026-09-03

The Website Page Templates file already has its own local `Section Title / Eyebrow` **component set** (distinct from the one built in MNG Design System on 2026-09-02 — see note below) with a `Style` variant property (`Underline` / `Bold`) **and** a `Chevron` boolean toggle, and it's already instanced consistently across all 12 section title placements in the assembled desktop template (Top Zone's Latest Headlines, the Sports/The Know/Don't Miss rails, Most Popular, Photos, and 6 generic placeholder titles). - **One real bug found and fixed:** the Top Zone's "Latest Headlines" instance had `Chevron=true`. Live-checked ocregister.com: `Latest Headlines` renders as plain `<h2><span>` text with no link and no icon, while `Local News`, `Sports`, `High School Football`, `Photos`, `Things To Do`, and `Opinion` are all real links with a chevron icon. So `Chevron` should only be on for section titles that link to a full section page. Set Top Zone's Latest Headlines to `Chevron=false` (now matches Most Popular, which was already correctly `false`). Everything else checked out already correct.
- **Resolved 2026-09-03:** the duplicate `Section Title / Eyebrow` component set in MNG Design System (built earlier the same day, `Style=Underline`/`Style=Bold`, no Chevron support) has been **deleted**. The Website Page Templates version — the one already in active use, with the Chevron property and correct variable bindings — is the single source of truth. No further reconciliation needed.

**Follow-up fix, 2026-09-03 — underline spacing & width:** Karl caught two more inaccuracies in `Style=Underline` by comparing against ocregister.com directly:
- **Gap:** production has visible breathing room between the title/icon row and the rule. Measured on both a linked category header (`Sports`, `padding-bottom: 6.25px`) and the non-linked `Latest Headlines` (`padding-bottom: 6.25px`, identical) — confirmed consistent across contexts. The component had 0px gap between its "Title Row" and "Rectangle." Fixed: set the master component's `itemSpacing` to 6px.
- **Width:** production's rule spans the **full width of the eyebrow's containing column**, not just the width of the title text/icon (e.g. `Sports` text+icon is far narrower than the 296px-wide column it sits in, but the linked element is `display:flex` at the full 296px, so the 2px rule stretches the whole way). The component itself was already built correctly (`layoutSizingHorizontal: FILL` on both the master component and its internal Rectangle) — but every placed **instance** in the template had gotten overridden to a fixed width matching the old hug-content size.
  - First pass fixed the 12 instances in the assembled desktop template.
  - Karl flagged this needed to apply everywhere the eyebrow appears, regardless of whether it sits above a single column or a multi-column block. A full sweep of the Homepage page found **38 total instances** (assembled desktop, the "Home Page Sections" library, and the mobile assembly/library) — **19 were still fixed at 212px** in containers as wide as 964px. All 38 are now confirmed `layoutSizingHorizontal = FILL`, verified with screenshots (e.g. a header in a 956px-wide container now correctly spans the full 956px, not 212px).
- **Cross-check on the Bold-style pattern:** audited Orlando Sentinel's other homepage module headers (Local News, Sports, Advice, Photos, Entertainment, Election, etc.) beyond just Latest Headlines — **none of them have any rule at all** (`border-bottom: 0px none` across the board). So the "Bold" style's lack of an underline isn't specific to non-linked titles like Latest Headlines — Bold-pattern sites simply never use a rule under any section title, anywhere on the homepage. No change needed to the `Style=Bold` variant; confirms it was already built correctly with no rule.

### 3.15 Real overlap fix + labeled containers — done 2026-09-04
Karl flagged that some components in the new `Components` catalog were still overlapping, or sitting in containers too small for their contents, and asked for 16px padding between components, 40px margins around component containers, and component/variant labels inside the containers.

- **Root cause of the overlap:** the previous pass (3.14) positioned variants using each component's *declared* width, but several component sets turned out to have **auto-layout enabled on the set itself** (a side effect of how `figma.combineAsVariants()` builds a set) with their variants set to `layoutPositioning: AUTO` — meaning manually setting a variant's `x` silently does nothing; real position is controlled by the set's own `itemSpacing` and child order instead. `TopZone Article Card`, `Newsletter Signup`, and `Zone 1 Lead Article Card` were still Desktop-first as a result (fixed by reordering the actual children array, not just `x`). Separately, `TOP ZONE Block`'s Desktop variant has an internal element ("Frame 11645") offset −87px from its own left edge — a pre-existing content bug, not something introduced this session — which caused real, measurable overlap with the Mobile variant next to it once the gap was tightened.
- **Fixed using true rendered bounds, not declared width.** Every device-variant pair/trio was re-measured with `absoluteRenderBounds` (the actual visual extent, including any bleed) rather than trusting `width`, then spaced to a real 16px visual gap: `itemSpacing` set to 16 for the five sets with no bleed, and to 103 for `TOP ZONE Block` specifically (16 + the 87px bleed it needs to clear) — flagging that −87px offset as worth a look, since it's a genuine content bug independent of this cleanup.
- **Built an actual container per component.** Every one of the 15 components/component-sets in the catalog is now wrapped in its own bordered card frame (white fill, light gray 1px stroke, 8px corner radius) with 40px padding on all sides, containing: the title, the description, a row of small teal variant-name labels (e.g. "MOBILE," "DESKTOP," "MOBILE · NARROW") sized and spaced to line up with the swatches below them, and the component itself. The whole `Components` frame is now one auto-layout stack (40px gaps between cards) so nothing needs manual position math going forward — it just re-flows.
- **One follow-up fix:** the `Article Status Badge` set's "None" variant is a near-zero-width placeholder, which broke its auto-sized label; gave that one label a 60px minimum width so it reads correctly instead of wrapping character-by-character.
- Re-verified both assembled pages via screenshot afterward — unaffected, since none of this touched instance content, only the documentation-only container frames and each set's own internal `itemSpacing`/child order (neither of which affects how instances elsewhere render).
